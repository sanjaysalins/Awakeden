## Independent review — Swirls of Life series plan

I verified this against the actual codebase rather than taking the artifact's claims at face value.

**`pipeline/series.py` schema claim checks out.** `load_series()` reads exactly `id/name/brand/concept/hook_pattern/cta_pattern/guardrails` and per-episode `title/primary_ref/refs/theme` — the paste-ready JSON block will parse cleanly. Cross-references to existing series (`Encounters`, `Miracles-as-Signs`, `Questions-Jesus-Asked`, `Parables`, `Types & Shadows`, `Jesus-in-OT`) were checked against `data/series.json` and are accurate, including the careful "(Matthew's account)" hedges where the plan borrows dialogue from a different gospel than the source series' `primary_ref`.

**Finding 1 (high) — the plan's build 2-6 spend assumes pipeline integration that doesn't exist and isn't named as a risk.** Every "validated" render this plan leans on (Hem F04/F05, Thomas F01, Storm F06) lives in `F:\slk\PycharmProjects\JesusInTheBible\poc_living_water_ink_style_test\test_the_cross\` as one-off scripts (`render_the_hem.py`, `render_the_thomas.py`, `render_the_storm_f06.py`, `build_deterministic_pass.py`) that call Higgsfield directly. None of it goes through `pipeline/visual_engine.py`'s `discover_scenes`/SP-G1-G9 gates, `pipeline/visual_render.py`'s content audit, or the `scene_plan.json` "scene" unit at all — a swirls "page" (baked title, frame number, 3-panel row, one big illustration) is a structurally different artifact. The project's own same-day memory states this plainly: "not wired into the production pipeline (`cli_visual.py`/`config.py` STYLE_REGISTRY)." Yet build step 2 says "run the whole pipeline: /narrate → /voice → pages → cut → landing-hold → captions" as if `/scene-plan`, `/stills`, `/assemble` (with AS-G6 hero-bookend, AS-G7 gospel-frame-survival gates) just work on pages — and section 6's risk table never mentions this gap at all, despite naming five smaller risks. This is the single largest unaddressed risk in the plan and it gates ~$80-100 of the six-build spend.

**Finding 2 (medium) — "validated" in the episode table conflates three different readiness axes.** Ep 03 (Thomas) shows "F01 validated," but the same-day memory records the user's actual verdict on F01: "the swirl's placement doesn't read... feels very basic." Section 6 does list this, but the table's own Status column still says "validated" — a producer scanning the table would miss it. Same issue on ep 04 (Peace Be Still): "F06 validated" tested only the storm/water rendering with zero Fray on any disciple; build 3 explicitly calls the Fray-on-multiple-figures test still open. "Art style proven," "motif proven for this specific episode," and "narration locked" are three different things currently collapsed into one word.

**Finding 3 (medium) — committing this entry has an uncosted side effect on every other series.** `render_series_library()` in `pipeline/series.py` loops over *all* series unconditionally to build the cross-series context block injected into every `/narrate` call's cached system prompt. "Strict schema... drops in clean" is true for JSON parsing but not for the prompt cache — the moment this commits, every future narration call across the whole project (not just swirls episodes) grows by this series' concept/guardrails text and busts the existing cache at least once. Worth naming explicitly rather than implying the change is inert.

**Finding 4 (low-medium) — cost estimates cover art/audio only.** Section 4/5's per-episode and per-build dollar figures are stills + clips + regen + audio. Per finding 1, builds 2-6 are the *first* time this content goes through `/narrate`'s tournament + 6-panel review + red-team + 5-CLI panel — the project's own cost model budgets ~$5-6/episode for that Opus work elsewhere. Say whether it's folded in or omitted.

**Finding 5 (low) — unconfirmed whether ep 14 re-covers already-shipped ground.** The dual-home policy explicitly confirms Bronze Serpent (behind ep 11+12) already shipped as a produced long-form. It doesn't confirm or deny the same for "The Passover Lamb" (behind ep 14), which the same policy paragraph would need to cover.
