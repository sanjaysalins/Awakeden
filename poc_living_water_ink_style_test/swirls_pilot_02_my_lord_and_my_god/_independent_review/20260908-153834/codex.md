# Independent review — codex (OK, 295s)

## Findings

1. **The unattended run will pause unless the human changes a setting first.** The plan says, *“without pausing for approval”*, but Flow’s Agent asks permission before credit-consuming actions by default. The user must set **Confirm before generating → Never** before submitting the run sheet; telling the Agent not to pause does not change that setting. This prerequisite is absent. [Google Flow Agent documentation](https://support.google.com/flow/answer/17093911?hl=en)

2. **“18 generations” materially understates execution and cost.** The retry rule permits 18 initial attempts plus 18 retries: **18 assets, but 18–36 generation attempts**. Furthermore, *“If Flow gives you more than one candidate … keep exactly one”* fails to prevent paying for unwanted candidates: Flow charges per generated output, not per request. The plan must explicitly set the Agent’s image/video output count to one before running. [Flow credit documentation](https://support.google.com/flow/answer/16526234?hl=en&ref_topic=16908930)

3. **There is no model, resolution, subscription, or maximum-credit budget.** Different eligible 8-second video models currently range from roughly 5–100 credits per clip. Eight videos therefore cost roughly 40–800 credits before retries and up to 80–1,600 if all video retries are consumed, excluding any other chargeable outputs. Model choice also changes feature support and output quality. *“8 seconds (or Flow’s nearest available length)”* is obsolete ambiguity: current supported models explicitly offer 8 seconds, but not all models support the same reference/edit features. [Supported models](https://support.google.com/flow/answer/16352836?hl=en) The plan needs a named model, resolution, account tier, output count, expected cost, and hard spend ceiling.

4. **The “fully self-contained” and splitting claims are false.** The header says, *“split it at any `### Step` boundary”*, but the actual primary headings are `## Step R1`, `## Step R2`, etc.; the named boundary does not exist. More seriously, *“Each step stands alone”* is contradicted by downstream dependencies on generated references, prior stills, global retry rules, and the final-report template. S3 requires the lamp to be dimmer *“than in STILL_02”* while rule 2 says, *“Carry nothing forward … except the images the step names by label”*—and S3 attaches only `REF_THOMAS`, not `STILL_02`. S4 similarly demands a door *“exactly as drawn before”* without attaching the prior room or door.

5. **The plan directly contradicts its declared companion source.** It claims, *“Nothing in this file contradicts that one.”* Yet R1/R2 say, *“Ingredients: none. This reference is made from the text alone”* ([run sheet](/F:/slk/PycharmProjects/JesusInTheBible/poc_living_water_ink_style_test/swirls_pilot_02_my_lord_and_my_god/FLOW_RUN_SHEET.md:123)), while the companion explicitly attaches `thomas_ref_hd_face.png`, `thomas_ref_hd_full.png`, and `jesus_ref_upscaled3x.png` ([brief](/F:/slk/PycharmProjects/JesusInTheBible/poc_living_water_ink_style_test/swirls_pilot_02_my_lord_and_my_god/GOOGLE_FLOW_BRIEF.md:306)). Those files currently exist. The brief also requires both references to be approved before story generation ([brief](/F:/slk/PycharmProjects/JesusInTheBible/poc_living_water_ink_style_test/swirls_pilot_02_my_lord_and_my_god/GOOGLE_FLOW_BRIEF.md:66)); this sheet explicitly removes that gate. This is already source-of-truth drift at the most consequential step.

6. **Several animation requirements are internally contradictory.** In CLIP_05, Thomas’s hand must *“inch closer”* while *“the hand-gap itself … stays fixed”* ([run sheet](/F:/slk/PycharmProjects/JesusInTheBible/poc_living_water_ink_style_test/swirls_pilot_02_my_lord_and_my_god/FLOW_RUN_SHEET.md:555)). In CLIP_06, his shoulders and chest must visibly change while his linework remains *“exactly as drawn, stroke for stroke”* ([run sheet](/F:/slk/PycharmProjects/JesusInTheBible/poc_living_water_ink_style_test/swirls_pilot_02_my_lord_and_my_god/FLOW_RUN_SHEET.md:636)). A generative video model cannot move a drawn body without changing the pixels and contours that represent it. These checks cannot all pass simultaneously.

7. **The QC mechanism assumes capabilities and precision not established for Flow’s Agent.** Official documentation lists generating, editing, organizing, and batch-generating media; it does not promise autonomous full-duration audiovisual inspection, exact first/last-frame comparison, anatomy counting, or reliable evaluation of subtle line-character differences. [Agent capabilities](https://support.google.com/flow/answer/17093911?hl=en) Requirements such as *“pixel-for-pixel identical”* are especially unsound after generative redraw and video compression. First-versus-last-frame checks are also invalid for periodic motion: a correctly flickering lamp or swaying halo can coincidentally return to a similar phase at the endpoint.

8. **The retry policy wastes money and propagates failed foundations.** The instruction is always one **unchanged** retry, then *“keep the better of the two … and continue.”* An unchanged retry does not address systematic failures caused by prompt overload, contradictory constraints, typography, or unsuitable model choice. Worse, a defective `REF_THOMAS` or `REF_JESUS` poisons up to 16 downstream assets while the sheet forbids regenerating the reference. A reference failure, bad likeness, malformed anatomy, wrong text, or closed hand-gap should be fail-closed—not silently accepted and animated.

9. **The still prompts are substantially overloaded.** Each interior still asks one generation to produce exact typography, exact panel count and layout, several caption strings, multiple figures, reference likenesses, correct hands, historical costume, cross-shot room continuity, and highly specific per-character line treatments. The plan itself records previous caption truncation, yet doubles down on one-pass image-model typography. Exact titles, frame numbers, and captions should be composited deterministically after generating clean artwork—or use Flow’s dedicated Type Overlays/Image Editor tools—rather than treated as probabilistic image content. [Flow tools](https://labs.google/fx/tools/flow)

10. **Existing repository QC is bypassed.** The workspace already contains [swirls_verify.py](/F:/slk/PycharmProjects/JesusInTheBible/poc_living_water_ink_style_test/swirls_verify.py), [flow_check.py](/F:/slk/PycharmProjects/JesusInTheBible/pipeline/flow_check.py), [clip_anim_qc.py](/F:/slk/PycharmProjects/JesusInTheBible/pipeline/clip_anim_qc.py), and [check_landing_hold.py](/F:/slk/PycharmProjects/JesusInTheBible/check_landing_hold.py). The run sheet replaces these repeatable checks with Agent self-reporting. That is duplication with weaker evidence, particularly given the documented prior zero-motion and morph defects.

11. **The plan stops before the deliverable exists.** The stated episode is “60-second,” but the actual assembly plan requires a 64.3-second finished cut, including a mandatory three-second landing hold. Shot 5 requires about 12.8 seconds and Shot 8 about 11.6 seconds, while this run produces only 8-second clips ([assembly plan](/F:/slk/PycharmProjects/JesusInTheBible/poc_living_water_ink_style_test/swirls_pilot_02_my_lord_and_my_god/ASSEMBLY_PLAN.md:37)). There is no extension/hold, assembly, narration mux, audio-duration parity, or landing-hold verification step. The existing `_assembly_v2/build_cut.py` is also still wired to six old filenames, not the eight new ones.

12. **The completion protocol contradicts failure handling.** Section 6 says completion requires *“all 18 labels … exist”*, while earlier rules allow Flow refusal and instruct the Agent merely to record the refusal. Both conditions cannot hold. The ending also says, *“name your downloads accordingly when you send the zip back,”* even though the preceding sentence says the human will download the assets and Flow’s Agent is not instructed to create or send a zip.

VERDICT: REVISE
TOP FIXES:
1. Run a gated smoke test first, then require human approval of both references before authorizing downstream spend; add fail-closed checkpoints for reference, typography, anatomy, contact-gap, and motion failures.
2. Specify Flow prerequisites and economics: Confirm-before-generating off, exact model/resolution, one output, supported 8-second mode, subscription assumptions, per-attempt credit estimate, and a hard maximum-credit budget.
3. Reconcile the two source documents and wire the real pipeline end to end: deterministic text compositing, repository QC tools, eight-shot assembly, required extensions/holds, narration mux, and the 64.3-second landing-hold gate.
