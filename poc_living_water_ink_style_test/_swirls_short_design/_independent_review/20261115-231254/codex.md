# Independent review — codex (OK, 391s)

The plan needs revision before further build work or spending. Its main problems are incompatible gate rules, incomplete recovery paths, and quotes that do not reliably describe the calls being made.

1. **BLOCKER — The voice workflow contradicts its spend rules.** Step 2 orders `voice -> ok voice_ear -> align`, but §5.4 says the voice grant closes at **“voice_ear”** and **“A grant dies … when the step’s closing gate is recorded.”** Alignment is paid. Additionally, Step 2 places **“Close the row”** after alignment, although an open voice row blocks another paid command. The current code contains an alignment exception and its dry run inserts confirmations missing from the plan. Specify one consistent lifecycle, including failed alignment and retakes.

2. **BLOCKER — Reference provenance forbids the references the pilot requires.** Step 4 says **“Crop refs by hand”**; G14s requires **“every still and ref PNG”** to equal a confirmed spend row’s `output_sha256`. Cropping changes that hash. The companion pilot brief also requires the existing `jesus_ref.png`, which has no receipt from this episode. G14s is explicitly non-overridable. Define permitted source assets and verifiable crop derivations. Also exempt a reference’s originating page from the requirement to send that reference: f04 cannot consume crops that are created from f04 afterward.

3. **BLOCKER — The R1 fallback cannot satisfy the guard.** §5.6 says missing provider billing/settings fields can be resolved when **“the owner accepts the tariff figure.”** But §5.3 requires numeric `credits_spent` and matching provider-record `sent_params`; missing fields leave the row unresolved, blocking every subsequent purchase. SWS-G0 cannot be overridden. Owner acceptance therefore has no defined executable effect. Probe existing creation records first, then either specify an explicitly weaker settlement mode or stop the pilot if those records lack the required evidence.

4. **MAJOR — Atomic claim does not provide complete crash recovery.** §5.2 saves `creation_id` **“the moment the generate tool returns.”** A provider can accept the purchase before the tool returns, or the servicer can die before saving that ID. The request is already claimed, cannot be voided, and `fetch` has no ID to fetch. There is also a crash window between appending the spend row and publishing the request. T6 tests killed clients, but omits these servicer and publication failures. Add fault-injection tests at each transition and a documented reconciliation path; probe whether provider-side idempotency or request correlation exists.

5. **MAJOR — Music is quoted using fewer seconds than the copied script buys.** §5.5 says **“score = seconds x rate.”** The ep16 script being copied requests Part 1 with `+2.5 s` and Part 2 with `+8.0 s`. A 45-second film therefore orders **55.5 seconds**, 23.3% above film duration, before any reroll. That exceeds the guard’s 10% reservation margin. Quote the actual two request lengths and the particular part allowed to reroll. T14 currently checks filenames and silence, not billing quantities.

6. **MAJOR — “Cached turns cost 0” conflicts with the three-pass voice procedure.** §5.5 prices uncached turns only, but Step 2 unconditionally removes narrator files before pass 2 and moves character files aside before pass 3. A warm rerun can therefore quote cached work as free and then purchase it again. Cache validity also depends only on `narration-tagged.md`, ignoring changes to `voices.json` and synthesis settings. Build the exact dispatch list before quoting, bind cache entries to their full inputs, and test warm and interrupted reruns.

7. **MAJOR — The audio check permits meaning-changing Scripture errors.** G2w fails only above **25% unmatched words per unit** or **10% overall**. In the 12-word line “John said I am not the Christ to all those who asked,” dropping **“not”** produces only 8.3% unmatched locally and 1.25% in an 80-word film. It passes while reversing the claim. T10b’s wholly different turn does not test this failure. Add omitted negations, substitutions and insertions; require explicit listening and resolution for discrepancies inside Scripture spans.

8. **MAJOR — The written moving-hold formula accepts a perfectly frozen clip.** G15h requires every window to be **“at least `k x N`.”** When the frozen control has zero frame difference, `N=0`; a frozen candidate also has zero difference and passes `0 >= k×0` for every possible `k`. The changelog promises an “absolute floor,” but the binding algorithm omits it. Specify a positive absolute threshold and zero-noise fixtures. The current implementation already contains an absolute floor that the plan needs to document.

9. **MAJOR — The human proof arrives after a substantial infrastructure build.** §9.2 requires phases A–C before the first paid picture, while §12 admits **“Real seed viewers are the only proof.”** No viewer sample, comprehension criterion, or stop decision is scheduled. Panels and an owner reviewing the work do not establish audience comprehension. Add a bounded viewer test using the earliest hold or animatic, and identify which remaining automation can wait for that result. The $10.62 render ceiling omits the dominant cost: implementation and attended review time.

10. **MEDIUM — The new ledger loses existing spend-report integration.** §5 introduces episode-local `spend_log.jsonl`, but provides no route into the existing `data/spend_ledger.jsonl`. The current `AGENT_BRIDGE.md` explicitly requires that ledger update so `/spend` and `/cost` remain accurate; `pipeline/cost.py` already exposes recording functions. Reuse or adapt that reporting interface, with a coordinator task if the lane prevents it. Two disconnected accounting records create misleading totals.
