# Independent review — claude (OK, 165s)

Reviewed as an adversarial plan check. Findings below, cited to exact lines.

## Concrete defects

**1. Retry-budget math is wrong, and it's the number feeding the cost-safety gate.**
Global Settings states: `Retry budget, CRITICAL checks... 2 extra attempts (3 attempts total)`, and Section 0.5 point 3 says: *"up to 2 extra retries on CRITICAL checks... so the real range is 20-45 generation attempts."* But every single one of the 20 steps (R1-R4, S1-S8, V1-V8) has at least one line marked **CRITICAL** in its checklist. Worst case is therefore 20 × 3 = **60** attempts, not 45. This isn't cosmetic — Section 0.5 point 3 explicitly tells the user to *"multiply [per-generation credit cost] by up to 45, and confirm that's a spend you're happy with"* before pasting an unattended run that "can't ask me anything mid-session." The one financial pre-flight check in the whole document is built on an undercount of ~33%, and three of the eight clips are the expensive "LONG — longest available" tier. Fix the number (60) in both places it appears (Section 0.5 point 3 and the Global Settings table) before this gets pasted.

**2. A doctrinally-loaded ambiguity is resolved silently, not escalated.**
The note under Step S5 says the source `_DESIGN_BRIEF.md` §3 summary table lists Jesus as absent from F04, while §6's actual scene description has him handing Judas the sop — and the run sheet just picks §6 and moves on ("Flagging this so nobody 'fixes' it back to the summary table's version later"). This is CLAUDE.md's own territory: *"If multiple interpretations exist, present them — don't pick silently"* and the non-negotiable that doctrine be *"verified BOTH independently... AND by the 5-CLI panel."* Whether Jesus is shown directly handing Judas the sop (a specific, contestable reading of John 13:26-27) is exactly the kind of call this project's own process routes through review, not through a footnote in a generation run sheet. This should go back to the user (or through independent_review.py) before spend, not be settled inline.

**3. Phase 1 refs are a single point of failure with no early human checkpoint, and CLAUDE.md's own memory says exactly this defect mode recurs.**
`Do not regenerate REF_JUDAS, REF_DOORWAY, or REF_SUPPER_ROOM` (repeated after every step that uses them). If a ref's best-of-three attempt still has a real defect (e.g. Judas reads even slightly villain-coded, or the room gains an ornament), that defect silently propagates into 5-10 downstream generations (S1/S3/S4/S5/S6 and their clips) before a human ever looks, since Section 0 mandates *"I am not watching between steps."* The plan's only mitigation is a Flags note after the fact — by which point the credits are already spent. Given how much of this document's design weight sits on Judas-looks-ordinary and the motif zone-separation (both stated once, at the top, never reinforced mid-run), a single lightweight checkpoint after Phase 1 (4 generations, cheap) before committing to Phase 2/3 (16 generations, expensive) would catch this for a fraction of the cost.

**4. The plan doesn't reuse this project's own established QC lessons for this exact art style.**
Memory `feedback_baked_text_needs_full_zoom_check.md` (this repo's own prior finding, same hand-lettered-caption-on-ink-and-watercolor style): *"a moderate-zoom look at handwritten captions isn't enough to catch a dash rendering as a pasted typeset glyph; zoom 2x+ on the actual pixels."* None of the eight storyboard-still checklists (S1-S8, each of which bakes 2-5 short handwritten strings) instruct a zoomed pixel-level check — only "reads exactly / no other text." Same gap for `feedback_animation_motion_check_by_pixel_diff.md` ("a contact sheet can't tell 'stable' from 'frozen'; measure pixel diff between frames") — the clip checks (V1-V8) rely on eyeballing first-vs-last frame, never a measured diff, and the closing "After the zip comes back" section (which is supposed to be the thorough human pass) only re-runs the ZONE check, not a text-zoom or motion-diff pass. Given CLIP_02's blink and CLIP_07/08's drifting ink are precisely the subtle-motion class that memory was written about, this is a real gap, not a nitpick.

**5. Section 0 rule 1 asks the *agent* to find and disable a UI setting it likely can't reach.**
*"If Flow offers any prompt-enhancement, auto-improve, or rewrite option, turn it off for this whole session"* is addressed to the agent mid-conversation, while Section 0.5 has the *human* pre-toggle two adjacent settings (confirmation prompts, output count) before pasting anything. If prompt-enhancement lives in the same settings surface as those two, it's more reliable to have the human toggle it once in Section 0.5 than to trust a tool-calling generation agent (whose visible actions are `generate_image`/`generate_video_with_first_frame`, not UI control) to locate and flip a setting through conversation alone.

## Reuse / cost
No duplication of the repo's own image/video providers — this is explicitly a separate Google Flow pilot track (consistent with the validated pilot process in memory), so that's fine. But it doesn't fold into the project's existing "cost" skill discipline (pre-flight + ledger log) despite that being standing practice for every other metered batch in this repo — worth at least logging the real spend afterward the same way HF/NBP/Kling runs do, rather than leaving cost as a one-time paragraph with no record.

## Feasibility, generally
The core structure (labels, running log, per-step retry/CRITICAL protocol, ZONE check) is sound and matches the already-validated pilot pattern. The main risk is document length/density: ~9,000 words of instructions front-loaded once, with the two hardest constraints (Judas-ordinary, motif-zone-separation) stated only in Section 0 and never re-anchored per phase — a real instruction-drift risk for a single long agent session, which the document's own closing section tacitly concedes by saying the label/filename mismatch "was real and expected to recur."

VERDICT: REVISE
TOP FIXES:
1. Correct the retry-budget arithmetic (45 → 60 worst-case attempts) in Section 0.5 point 3 and the Global Settings table before anyone uses it to set a spend ceiling.
2. Escalate the F04 Jesus-presence ambiguity (Step S5 note) to the user or the independent-review process instead of resolving it unilaterally inside the run sheet.
3. Add a human checkpoint after Phase 1 (4 cheap generations) before committing to Phase 2/3 (16 expensive generations), since a flawed REF_JUDAS/REF_SUPPER_ROOM currently cannot be regenerated and cascades silently into 5-10 downstream generations.
