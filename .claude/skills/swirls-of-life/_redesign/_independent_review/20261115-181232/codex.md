# Independent review — codex (OK, 453s)

Several claimed code checks are incorrect, and key safeguards lack an implementable integration.

1. **HIGH — The spend guard cannot inspect receipts through the proposed interfaces.** §3 requires “`credits_spent` must be a number,” but §4.5 freezes the renderers and bridge. The renderers consume the response, print its credits, and return only a Boolean. See [swirls_page.py:388](F:/slk/PycharmProjects/JesusInTheBible/poc_living_water_ink_style_test/test_the_cross/swirls_page.py:388). Calling a guard before rendering cannot implement post-request reconciliation. Define the receipt interface and recovery for a timeout after billing. Also explain how voice, music, poster and manual reference renders obey “every later paid command refuses”; the code plan guards only `still` and `animate`.

2. **HIGH — SWS-G14 can certify an old clip against a new still.** The claim “the json stores the still’s sha256” does not establish which still generated the video. Existing `render_animation()` skips any existing MP4. Replace the PNG, rerun animation, then rerun `clipqc`: the old MP4 survives, and QC can record the new PNG hash. See [swirls_page.py:398](F:/slk/PycharmProjects/JesusInTheBible/poc_living_water_ink_style_test/test_the_cross/swirls_page.py:398). Record provenance when generation is submitted, bind it to the resulting video hash, and test this exact sequence.

3. **HIGH — The proposed publish anchor does not match the parser.** Step 0 prescribes line 1 as `Psalm 41:9; John 13:18-27`. `_swirls_anchor_ref()` requires a reference followed by `(`; that example fails and silently falls back to the cover subtitle. Furthermore, the parser extracts one reference, so adding parentheses does not preserve the paired passages. See [upload_engine.py:168](F:/slk/PycharmProjects/JesusInTheBible/pipeline/upload_engine.py:168). The asserted “exact verse range … on every platform” is unsupported.

4. **HIGH — The supposed KJV gate neither exists at the stated path nor guarantees verbatim Scripture.** Step 1 names `PythonProject1\jesus\narration\narration_pipeline.py verify`. The actual script is `PythonProject1\jesus\narration_pipeline.py`, invoked with `<folder> --stage verify`. Its verify stage performs input checks and an LLM content review; it can return success even when that review errors. It is not an exact KJV comparison. Correcting the command alone will not supply the promised Bible gate.

5. **HIGH — Reference bootstrapping still blocks the stated order.** Step 3 says `plan` runs “the old SW lints plus” SWS-G7a. Existing `cmd_plan()` unconditionally runs `sw_l4_refs_exist()` across every spec, before Step 4 creates those references. See [swirls_episode.py:88](F:/slk/PycharmProjects/JesusInTheBible/poc_living_water_ink_style_test/swirls_episode.py:88). Explicitly defer that old check for trim planning and define how the north-star spec temporarily uses only the Jesus reference. There is another bootstrap gap: `timing` precedes creation of `episode.py`, while the current dispatcher imports that file before handling any command.

6. **HIGH — The reused Vision helper discards the proposed audit data.** §4.2 specifies calling existing `swirls_verify._vision_audit`, while SWS-G9 expects `texts_seen`, `head_count`, and individual answers. That helper converts responses into `ImageAudit`, whose parser retains only `passed`, `issues`, and `banned_token_hits`. See [visual_models.py:271](F:/slk/PycharmProjects/JesusInTheBible/pipeline/visual_models.py:271). Define a structured response adapter. Version the audit cache and include the expected spec in its key; a PNG hash alone cannot distinguish an old audit from the new rubric.

7. **MEDIUM — The alignment fallback is incompatible, and “$0” subtitle generation can repeat paid alignment.** Step 2’s ep16 `_align.py` writes a top-level list containing `{w,start,end}`. The shared reader expects an object containing `words` with `text` fields. The fallback also resolves its episode relative to its own location. Separately, `build_srt.build()` calls `align(force=True)`; with the ElevenLabs backend selected, draft assembly, scored assembly and Step 9 can each request another paid alignment. Reuse a validated alignment through a defined schema and account for regeneration explicitly.

8. **MEDIUM — The hold correction conflicts with the per-unit tolerance.** §4.1 assigns all accumulated rounding error to the back unit, while SWS-G15 requires *each* held unit to match its slot within one frame. Six pages each losing 0.01 seconds would extend the back by 0.06 seconds—nearly two frames at 30 fps. Fractional slots are normal with word alignment. Allocate frames from cumulative boundaries and test fractional timings; whole-second synthetic clips will miss this defect.

9. **MEDIUM — The pace test does not validate the range it authorizes.** Section 1 asks whether pages can be read “in about 6 s,” but the three seats receive static images with unlimited inspection time. Its numerical pass condition checks only labels. Section 2 then permits pages as short as four seconds. An owner watching the films supplies useful evidence, but static transcription does not establish reading speed or comprehension. Test timed exposure at the shortest permitted slot, or constrain production slots to the demonstrated pace.

10. **MEDIUM — Two advertised branches contradict hard gates.** The pace-test fallback “5 pages at about 7 s” conflicts with eight units, eight narration lines, and the fixed F01–F06 motif map. Step 6a’s mandatory “turn page, 7 s” also conflicts with the calculated `clip_duration` and SWS-G3’s exact spec/timing equality whenever that page requires another duration. Specify consistent branches before describing the runbook as standalone.

11. **MEDIUM — The new edge classifier is premature, and its crop claim is false.** SWS-G10 proposes detecting “a drawn rule or blank band” from edge pixels without fixtures or a defined classifier. The existing cover Vision audit already checks borders and margin bands; justify duplicating that judgment before the pilot. Also, cropping “the same amount off all four sides” preserves aspect ratio only if the amount means a proportional fraction. Equal pixel crops change a portrait image’s ratio, causing additional distortion when scaled.
