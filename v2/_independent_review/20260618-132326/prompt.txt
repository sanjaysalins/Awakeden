## Phase 2 — Harvest the Eleven scores into a SEPARATE `eleven_music/` collection (mostly $0)

Per the user's decision, build a dedicated `eleven_music/` collection (mirror the music_library
tooling — `index.json` + ingest/approve/find_for_beat/qc — in the new dir; reuse the code
patterns, keep the store separate from the Suno `music_library/`):

1. **Ingest** the 11 generated `assembly/music.mp3` scores with `source="eleven"`,
   `license="eleven-music"`, provenance = the short they were made for.
2. **Tag** each from `music_designs.json`: lens (Minimalist-Ambient | Cinematic-Redemptive),
   mood (grief/intimate, redemptive-arc), beat, doctrine-fit. Keep the winning `best_prompt`
   so a near-match can be regenerated/extended later.
3. **Audition-gate** (`approve.py`) — only takes the user approves by ear become selectable.
4. `find_for_beat(beat, tags)` then returns the best eleven/suno score by fit (already built).

Result: a small **palette** (≈ 2 lenses × a few moods) covering most short/long beats.

## Phase 3 — Apply music to every rebuilt cut (reuse-first → mostly $0)

Per rebuilt short:
- `find_for_beat` the best-fit **approved** score from the library → mix at the **new directive**
  (`add_music.py` with gain −8, outro 2.5, gentle duck threshold 0.12 / ratio 2.5) → re-caption.
- Generate a NEW score ONLY if the library has no fit → then **add it to the library** (so it's
  reused next time). Metered (Eleven Music quota, invisible) — quote the count + ask first.
- #03 (already rebuilt) gets its music re-applied here (its old music final is stale).

This replaces "regenerate a bespoke score per short" (metered each) with **reuse after first gen**.

## Phase 4 — Wire the music library into LONG-FORM (and future shorts)

- Long-form audio pipeline: pull per-movement scores from `music_library` via `find_for_beat`
  (reuse-first, doctrine-gated), generate new only on no match, audition-gate, add back to the library.
- Future shorts: `add_music` / the music batch consult `find_for_beat` before generating.
- Net effect: the library turns recurring metered music spend into a **one-time palette cost** —
  the same generate-once-reuse lever as `clip_library` / `sound_library` / `image_library`.
