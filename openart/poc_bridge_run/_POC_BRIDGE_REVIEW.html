OpenArt Bridge POC — does it work?

Yes. The full loop worked, four times in a row: script asks for an image, I make it live, script asks for a video, I make that too, script moves to the next page on its own. This is the first time this had been tested for real (before this it was only a manual test, no live script).

What was made: 3 pages from episode 1 — F01 (no reference image), F02 and F06 (each with a reference image, testing the upload step too). Each got a still, then an animated clip from that still.
Cost: $0.39 (F01) + $0.39 (F02) + $0.64 (F06, longer clip) = $1.42 total. Logged.
Files did not touch the real episode 1 folder — these are test copies only.

Page 1 — F01 (no reference image)

Looks right. Small known issue (already seen before): the thin blue line pokes above the page border near the top — a known small OpenArt quirk, not new.

Found a defect: the handwritten label under panel 2 (“the cargo”) fades away and is gone by the end of the clip. The rule for these clips is that no text should ever change. This breaks that rule.

3.75s — label solid
4.67s — label fading
4.96s (last frame) — label gone

Page 2 — F02 (uses a reference image: the queen)

First real test of uploading a reference image through the bridge — worked cleanly. The queen matches her reference. The blue line stays properly inside the frame this time too.

No fade this time — checked 5 frames across the whole clip, every label stayed solid start to finish.

Page 3 — F06 (uses a reference image: Jesus, longest clip — 9s)

This is the exact page where the 2-line caption (“a greater than Solomon” / “is here”) broke last time — collapsed to one line with quote marks added. This time it rendered correctly, two clean stacked lines, no quote marks.

No fade here either — checked 6 frames across the full 9 seconds, every label stayed solid.

What this means

Good news: the bridge itself (script → me → OpenArt → back to script) works cleanly across multiple pages in a row, including uploading reference images. No code changes needed.

Real caution: both problems seen so far — the fading caption, and the broken 2-line caption — look like they come and go rather than happening every time. Out of 3 pages tested, only 1 showed the fade, and the 2-line-caption break didn’t repeat on a second try. That’s good news (not a guaranteed failure) but also means every OpenArt page still needs a real eyeball check before shipping — you can’t assume a clean run just because the last one was clean.
